MyAgent 用户使用文档

MyAgent 是一个基于 AI 的智能编程助手，支持代码阅读、编写、调试、文件管理、Git 操作等全流程开发工作。

工作空间切换器
会话列表
标题栏（项目名 + 分支）
输入框 + 工具栏
▲ MyAgent 主界面：左侧会话列表，右侧对话区 + 输入框

核心能力一览

  • 核心 智能对话：理解项目上下文，支持思考模式、多轮对话
  • 核心 文件管理：内置文件树、代码预览、Diff 查看
  • 核心 代码引用：选中代码片段或整文件，直接添加到对话上下文
  • Git 分支切换：在标题栏快速切换 Git 分支
  • Git Worktree：创建 Git Worktree 实现多分支并行开发
  • 交互 智能提问：Agent 遇到歧义时主动向你提问（单选/多选）
  • 技能 Skills 系统：/ 触发技能选择器，加载领域知识
  • 团队 Agent 团队编排：多 Agent 协作（流水线、并行、循环迭代等 9 种模式）
  • 自动 Autopilot 自动驾驶：分析→规划→执行→验证全自动循环
  • 子 Agent：委派子任务给独立的 AI Agent 处理，支持串行执行和中止
  • 定时任务：Cron 语法定时触发 Agent 执行

快速开始

输入框 + 工具栏
▲ MyAgent 启动后的欢迎界面：快捷提问按钮和底部输入框

1. 启动应用

在项目根目录执行：

pnpm dev

服务启动后，浏览器打开 http://localhost:5173。

2. 添加项目

首次使用，点击左侧侧栏顶部的工作空间切换器，选择「添加项目」，在文件浏览器中选择你的项目目录。

3. 开始对话

在底部输入框输入消息，按 Enter 发送。MyAgent 会根据你的项目上下文给出回答。

💡 案例：理解一个陌生项目
打开项目后，直接问："帮我看看这个项目用了什么技术栈，整体架构是怎样的？" MyAgent 会浏览文件树、读取关键配置文件（如 package.json、pom.xml），然后给你一份项目概览。

项目列表
添加 / 打开工作空间
▲ 工作空间切换器下拉菜单：列出所有已添加项目，底部可打开新工作空间

点击左上角「M」品牌图标 → 弹出工作空间下拉菜单 → 点击「添加项目」→ 在文件浏览器中选择目录。

切换项目

点击工作空间下拉菜单中的项目名即可切换。切换后会自动加载该项目的会话列表和文件树。

切换项目时，当前项目路径会显示在标题栏（hover 项目名可见 tooltip）。

在 Finder 中打开

标题栏右侧有文件夹图标按钮，点击在 macOS Finder 中打开当前项目目录。

💡 案例：同时管理多个项目
你可以添加多个项目（如前端 + 后端），通过工作空间切换器快速跳转。每个项目有独立的会话列表，互不干扰。

会话管理

▲ 侧栏会话管理：顶部 + 新建、Tab 切换、搜索入口；列表按今天/昨天/7天内分组，hover 会话显示 📍 置顶和删除按钮

新建会话

点击侧栏左上角 + 按钮或按快捷键 ⌘ N 创建新会话。每个会话有独立的上下文和消息历史。

切换会话

点击侧栏会话列表中的任意会话即可切换。会话按时间分组（今天、昨天、更早）。

置顶会话

点击会话右侧的 📍 按钮可以置顶/取消置顶。置顶的会话始终显示在列表最上方。

删除会话

点击会话右侧的删除按钮，确认后删除该会话及其所有消息。

搜索会话

按 ⌘ K 打开会话搜索，输入关键词搜索历史会话。

小贴士
会话会自动持久化到 ~/.myagent/chat-sessions/，刷新页面或重启服务不会丢失。

智能对话

▲ 对话输入区：支持文本/图片输入，🧠 思考模式和 🚀 Autopilot 开关

发送消息

在输入框输入文本，Enter 发送，Shift + Enter 换行。支持 Markdown 格式渲染。

发送图片

点击工具栏的 📎 按钮添加图片，或直接拖拽图片到输入框。如果当前模型不支持 Vision，Agent 会自动调用 analyze_image 工具识别图片内容。

思考模式 推荐

点击工具栏 🧠 按钮开启/关闭思考模式。开启后模型在回答前会先"思考"（输出推理过程），思考内容显示在对话区的「过程」面板中（默认折叠）。

思考模式适合复杂推理任务，如代码调试、架构设计、方案选择。

过程面板

每条 AI 回复上方有一个「过程」折叠面板，展开可以看到：

  • 思考过程：模型的推理链
  • 工具调用：执行了哪些工具（read、bash、search 等），输入输出详情
  • 技能加载：加载了哪些 Skill
  • 子 Agent：委派的子任务及其进度

停止生成

生成过程中点击右下角红色 ✕ 按钮可以中止当前生成。

重新生成

在最后一条 AI 回复下方有「🔄 重新生成」按钮，点击会重新执行上一轮对话。

💡 案例：开启思考模式调试 Bug
开启 🧠 思考模式后，问："这段代码为什么会报 NullPointerException？" 模型会先分析可能的原因，逐一排查代码，最后给出诊断。你能看到完整的推理过程。
💡 案例：发送截图让 AI 分析 UI
截图一个报错弹窗，拖到输入框，输入："这个报错是什么原因？帮我看看代码里哪里出了问题。" Agent 会识别截图内容并定位代码。

Agent 角色管理

Agent 下拉菜单
▲ Agent 选择器下拉菜单

什么是 Agent 预设

Agent 预设是一套带有自定义系统提示词（System Prompt）的角色配置。不同的 Agent 有不同的专业领域和行为方式。

切换 Agent

点击输入框工具栏最左侧的 Agent 按钮（显示当前 Agent 名称），在下拉菜单中选择。切换后当前会话会使用新 Agent 的角色指令。

创建 Agent 预设

点击下拉菜单底部的「管理 Agent…」→ 在弹窗中：

  1. 填写 Agent 名称（如 "代码审查专家"）
  2. 选择图标
  3. 填写系统提示词（如 "你是一个严格的代码审查专家，重点关注安全性、性能和可维护性…"）
  4. 可选：禁用某些工具
💡 案例：创建一个 Code Review Agent
创建 Agent：名称 "Reviewer"，提示词 "你是代码审查专家。审查代码时检查：1. 安全漏洞 2. 性能问题 3. 错误处理 4. 代码风格。给出具体的改进建议和代码示例。" 切换到这个 Agent 后，每次对话都会以代码审查的视角回答。

Agent 团队编排 新增

Agent/团队选择器
Autopilot
▲ Agent 选择器下拉菜单：上半部为普通 Agent，下半部滚动可见团队列表

Agent 团队是多 Agent 协作的高级模式。选择一个团队后，主 Agent 变为团队协调者，通过 delegate_task 工具把任务委派给团队成员（子 Agent）执行。每个成员有独立的上下文和专业角色，产出通过共享黑板传递。

团队 vs 单 Agent
单 Agent 模式下，Agent 自己处理所有任务。团队模式下，主 Agent 只负责协调和分配，实际工作由各专业成员完成。每个成员有隔离的上下文窗口，避免信息过载。

选择团队

点击输入框工具栏最左侧的 Agent 选择器，在下拉菜单的团队区域选择一个团队。选择后：

  • 当前会话绑定该团队（session 级持久化，切换会话自然恢复）
  • 编排指令注入 Agent 的系统提示（不是拼到消息里，后续每轮对话自动带上）
  • Agent 选择器显示团队名称和图标，稳定不跳变

9 种编排模式

模式图标说明典型场景
流水线 (Pipeline)➡️按顺序依次执行，前一步的产出传给下一步开发 → 审查 → 测试
主控调度 (Supervisor)🎯主控 Agent 智能分解任务，按需调度专家复杂项目分解
评估迭代 (Evaluator)⚖️执行后评估，不通过则带反馈重试代码质量打磨
并行 (Parallel)⚡所有专家同时处理同一任务，汇总结果多角度分析
辩论 (Debate)🗣️多轮辩论，最终达成共识技术方案决策
路由 (Router)🔀第一个成员分析请求并分派给最佳专家智能客服分流
分治聚合 (MapReduce)🧩大任务拆分为子任务，并行处理后汇总大规模重构
自定义流程 (Custom DAG)📐用户自定义节点依赖关系复杂工作流
循环迭代 (Loop)🔄执行 → 评估 → 不达标重试，死磕到底反复打磨质量

团队执行可视化

模式标题
后端工程师节点
代码审查员节点
▲ 团队执行流程图：后端工程师 → 代码审查员，节点状态实时联动

团队任务执行时，对话区顶部显示流程图（DAG 节点图），实时展示每个成员的状态：

  • 灰色：等待中（pending）
  • 蓝色/绿色（动态）：正在执行（running）
  • 绿色 ✓：已完成（done）
  • 红色 ✕：出错（error）

每个节点显示成员角色和耗时。切换会话时流程图自动清除。

共享黑板

团队成员通过共享黑板传递信息。每个成员完成后用 write_blackboard 写入关键产出，后续成员用 read_blackboard 读取前序步骤的结果作为上下文。

子 Agent 钻入查看

流程图节点（3 个成员的状态 + 耗时）
delegate_task 卡片 + 工具调用时间线
▲ 团队执行详情：顶部流程图节点 + 下方 delegate_task 卡片和工具调用时间线

每个 delegate_task 工具调用显示为可点击的卡片。点击进入子 Agent 的独立详情视图，可以看到：

  • 子 Agent 的完整对话过程（思考、工具调用、输出）
  • 实时执行状态（正在运行 / 已完成 / 出错）
  • Token 消耗和耗时统计

点击「← 返回主会话」回到主视图。每个 delegate_task 卡片正确对应其子 Agent，不会串台。

退出团队模式

在 Agent 选择器中选择任意普通 Agent（非团队），自动退出团队模式，重建为普通 Agent 会话。

💡 案例：流水线开发 Spring Boot 功能
选择「开发流水线」团队（后端工程师 → 代码审查员 → 测试工程师），输入"帮我新增用户注册功能"。主 Agent 按流水线依次委派：
1. 后端工程师实现功能代码（写入黑板）
2. 代码审查员读取黑板审查代码（输出审查报告）
3. 测试工程师编写并运行测试
全程串行执行，每个成员完成后下一个才开始。
💡 案例：循环迭代打磨质量
选择「代码精炼」团队（Loop 模式，后端工程师 + 代码审查员），输入"优化这个模块的代码质量"。后端工程师优化 → 审查员评估，如果不达标就带反馈重试，直到通过或达到最大循环次数。
注意
团队模式下，每一轮对话都会走完整的团队流程。简单追问（如"刚才那个改一下"）也会触发完整的委派流程。如果需要简单对话，请切换回普通 Agent。

Autopilot 自动驾驶 新增

设置导航
超时参数 + 提示词编辑
▲ Autopilot 配置页：设置最大循环次数和各阶段超时时间

Autopilot 是全自动任务执行模式。开启后，Agent 自动完成分析→规划→执行→验证四个阶段的循环，无需人工干预，直到任务完成。

开启 Autopilot

点击输入框工具栏右侧的 🚀 按钮开启/关闭 Autopilot。开启后发送消息，Agent 进入自动驾驶模式。

四个阶段

阶段说明产出
1. 分析 (Analysis)理解任务需求，分析现有代码需求分析和约束条件
2. 规划 (Planning)制定执行计划，拆分步骤具体执行方案
3. 执行 (Execution)按计划写代码、修改文件代码变更
4. 验证 (Verification)运行测试、检查结果通过/不通过 + 问题列表

如果验证不通过，自动回到规划阶段修正方案，循环执行直到通过。

实时进度

对话区实时显示 Autopilot 的当前阶段、轮次和每个阶段的输出摘要。你可以在任何时候点击停止按钮中止。

Autopilot 超时配置
Autopilot 每个阶段有独立的超时限制（默认 300 秒），可在设置页面调整。超时后会自动中止并提示。

📄 文件引用 chip
▲ hover 文件树中的文件点击 +，输入框上方出现文件引用 chip；右侧代码编辑器同步展示文件内容

在文件树中，鼠标 hover 到任意文件上，右侧会出现一个 + 按钮。点击后：

  1. 自动读取文件内容（超过 300 行自动截断）
  2. 在输入框上方显示一个带「全文」标签的 chip
  3. 发送消息时，文件内容会作为上下文附在消息末尾

查看已添加的文件

输入框上方的 chip 栏会列出所有引用。整文件引用显示 📄 图标和「全文」标签，代码片段引用显示 { } 图标和行号。点击 chip 上的 ✕ 可以移除。

💡 案例：让 AI 基于某个文件修改
在文件树中 hover 目标文件 → 点击 + → 输入 "帮我把这个文件里的数据库操作改成使用连接池" → 发送。Agent 会基于文件完整内容给出修改。
注意
每个文件最多添加 300 行到上下文。如果文件很大，Agent 会收到截断提示并自动用 read 工具读取完整内容。

Worktree 多分支并行 新增

什么是 Worktree

Git Worktree 允许你把不同分支检出到独立目录，共享同一个 Git 仓库。这样你可以同时操作多个分支，互不影响。

创建 Worktree

Worktree 创建对话框
▲ Worktree 创建对话框：输入新分支名、选择基分支、预览目标路径

点击标题栏分支名 → 底部「在新 Worktree 中打开…」→ 弹出创建对话框：

  • 新分支模式：输入新分支名 + 选择基于哪个分支创建
  • 现有分支模式：选择一个已有分支检出为独立目录
  • 底部显示 Worktree 的目标路径预览

点击「创建并切换」后，自动创建目录、注册为新工作空间、切换过去。

路径规则

Worktree 自动创建在主仓库的同级目录下，命名为 项目名-分支名。例如 newbee-mall-feature-login。

💡 案例：在不打断当前工作的情况下修复紧急 Bug
你正在 feature 分支开发新功能，突然需要在 main 分支修一个紧急 Bug。点击分支名 → 「在新 Worktree 中打开」→ 选择 main 分支 → 自动创建独立的 Worktree 目录。修复完 Bug 后，通过工作空间切换器回到 feature 分支继续开发，互不干扰。
Worktree vs 分支切换
分支切换（checkout）改变当前目录的文件内容，影响正在进行的工作。
Worktree另开目录，每个分支独立工作。适合需要频繁在多个分支间切换的场景。

什么是 MCP

Model Context Protocol (MCP) 是一种标准化的外部工具接入协议。通过 MCP 服务器，Agent 可以连接外部服务（数据库、API、本地工具等）获得额外能力。

配置文件

MCP 配置存储在 ~/.myagent/mcp.json，格式示例：

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-filesystem", "/path/to/dir"]
    }
  }
}
扩展 vs MCP
扩展（Extension）是 MyAgent 原生的 npm 包，直接注册为 Agent 工具。
MCP是通用协议，可以接入任何支持 MCP 的外部服务。两者可以共存，按需选择。

子 Agent 委派

delegate_task 卡片（点击钻入查看详情）
▲ delegate_task 卡片：每个子 Agent 委派显示为可点击卡片，展示执行时间线

功能说明

对于复杂任务，Agent 可以通过 delegate_task 工具委派子任务给独立的子 Agent 处理。子 Agent 在隔离的上下文中运行，完成后返回摘要。你可以在对话中点击子 Agent 卡片查看其详细的执行过程。

串行执行 改进

同一会话中的多个 delegate_task 调用强制串行执行。即使 LLM 在一个回合里同时发起多个委派，也会自动排队——前一个子 Agent 完全结束后，下一个才开始。这确保了团队协作模式中步骤的严格顺序性。

中止连锁 改进

当你点击停止按钮中止主 Agent 时，所有正在运行的子 Agent 也会被立即连锁终止。之前中止只影响主 Agent，子 Agent 会继续跑到超时。现在 abort 信号会传递给每个活跃的子 Agent，立即停止。

子 Agent 超时保护

每个子 Agent 有三层超时保护：

  • 空闲超时（180s）：长时间无任何产出活动则判定卡死
  • 硬超时（15 分钟）：绝对上限
  • 外部中止：主 Agent 停止时连锁触发

阻塞命令指导

子 Agent 的系统提示包含对阻塞命令的指导：遇到需要启动长时间运行的服务（如 web server），必须用后台方式（command & 或 nohup）运行，然后通过 curl 验证，避免直接阻塞。

💡 案例：并行研究 + 实现
你说："调研一下目前主流的 ORM 框架，然后帮我选一个集成到项目里。" Agent 可能委派一个子 Agent 去做技术调研（搜索 + 阅读），主 Agent 基于调研结果帮你集成。

开发模式

前后端同时启动，支持热重载（前端 HMR + 后端 tsx watch）：

pnpm dev

也可以单独启动：

pnpm dev:server   # 仅后端（tsx watch，端口 3000）
pnpm dev:web      # 仅前端（Vite，端口 5173）

开发模式下前端通过 Vite dev server 代理 API 请求到后端，修改代码自动刷新。

生产模式：统一 http://localhost:3000（后端托管前端静态文件）。

一键打包发布

将前后端打包为可独立运行的 npm 包（.tgz），安装后通过 myagent 命令启动：

pnpm pack:release

构建流程（scripts/build-release.mjs）：

  1. Vite build：构建前端 → packages/web/dist
  2. 拷贝前端：移动到 dist-release/public/
  3. esbuild bundle：后端 + workspace 扩展包打包为单文件 → dist-release/server/index.js
  4. 生成入口：创建 bin/myagent.js（CLI 入口）
  5. 生成 package.json：声明外部依赖（fastify、Pi SDK 等）

产物结构：

dist-release/
├── bin/myagent.js       ← CLI 入口（node bin，可直接执行）
├── server/index.js      ← 后端 bundle（含扩展包，不含 node_modules）
├── public/              ← 前端静态文件（HTML/JS/CSS）
└── package.json         ← 外部依赖声明

安装与运行

# 本地安装
cd dist-release && npm pack           # 生成 myagent-0.1.0.tgz
npm install -g ./myagent-0.1.0.tgz    # 全局安装

# 启动
myagent                                # → http://localhost:3000
myagent --port=8080                    # 指定端口
esbuild bundle 的作用
开发模式下后端用 tsx 直接运行 TypeScript，workspace 扩展包（orchestrator/subagent/todo）通过符号链接 import。打包时 esbuild 把后端代码和所有 workspace 包 bundle 为单个 server/index.js，无需保留 workspace 结构。运行时只需安装外部依赖（fastify、Pi SDK 等）。

常见问题

⚠️ 遇到问题 → 查看对话区错误提示 → 开启 Debug 面板 → ✓ 定位原因
▲ 排查流程：错误提示 → Debug 时间线 → 定位根因

Q: 对话报错 "余额不足" 怎么办？

当前使用的模型（如 glm-4.7）是付费模型，账户余额用完会报 HTTP 429 错误。MyAgent 会直接在对话区显示具体的错误信息（如"模型调用失败: xxx"），不会再出现空白气泡或卡死等待。可以在设置中切换到免费模型 glm-4-flash，或充值账户。

Q: Agent 回复是空白气泡或"模型调用失败"？

这表示 LLM API 调用出错。常见原因：API Key 过期、账户余额不足、模型限流（429）、网络超时。MyAgent 会在对话区直接显示错误原因。如果错误信息不明确，打开 Debug 面板查看原始 API 请求和响应。

Q: 子 Agent 执行很久后"被中止"？

子 Agent 有三层超时保护。如果 180 秒无任何产出活动（空闲超时）或超过 15 分钟（硬超时），会自动中止。常见原因是子 Agent 在等待一个阻塞命令（如 mvn spring-boot:run）的输出。子 Agent 的系统提示已包含阻塞命令的指导，但 LLM 不一定遵守。

Q: Skills 列表为空？

Skills 从 ~/.myagent/skills/ 加载。确保该目录存在且有 SKILL.md 文件。可以建一个 symlink：ln -s ~/.hermes/skills ~/.myagent/skills

Q: Agent 创建后需要重新创建？

Server 重启后 Agent session 会被销毁。发一条消息会自动重新创建 Agent。

Q: 图片无法被识别？

如果当前模型不支持 Vision（如 glm-4-flash），图片会存入队列并提示 Agent 调用 analyze_image 工具。确保 API Key 有效。

Q: 分支切换后文件树没更新？

分支切换后页面会自动刷新。如果没刷新，手动 Cmd+R 刷新页面。

Q: Worktree 创建失败？

常见原因：目标路径已存在、分支名包含特殊字符、没有写权限。查看错误提示中的详细信息。
